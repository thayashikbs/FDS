Chapter 5 一般化加法モデル (GAM)

本章の内容は, 授業の R 演習スクリプト R_gam_dist.R に対応する. 使用するデータは, いずれも授業用に作成した仮想データである. スクリプトの構成は, 参考書 ISLR2 の第7章 (Lab) を参考にした.

本章では, GAMを実行するパッケージとして, (参考書ISLRが使用している) gam, およびmgcvを紹介する. しかし, 後述のように, 二つのパッケージを同時に読み込むと プログラムの一部が正常に動作しなくなる可能性があるため, 一つのプログラムの中ではどちらか一方のみを使用するのが安全である. 特段の理由がなければ, mgcvのみを使用するのが良い.

  • mgcvの方が理論的により適切な計算を行っている (後述).

さらに,

  • mgcvの方が, より多様な機能を持っている. 例えば,
    • パッケージmgcvの関数gam()は, 説明変数間の交互作用をモデルに 取り入れられるなど柔軟性に富む.
    • パッケージmgcvの関数s()は, 多様な平滑化項を指定することができる.

5.1 データ: 社債の信用スプレッド (仮想)

- bond_spread.csv, 600銘柄
  - spread: 信用スプレッド (国債利回りとの差, bp) (目的変数)
  - leverage: 発行体の負債/総資産 (%)
  - equity_vol: 発行体の株価ボラティリティ (年率, %)
  - maturity: 残存年数 (年)
  - log_assets: 発行体の総資産 (対数)
  - industry: 業種 (manuf: 製造業, nonmanuf: 非製造業, utility: 電力・ガス)

このデータは, 構造型モデル (Merton モデル) の考え方に基づいて作成した. すなわち, 発行体のレバレッジと株価ボラティリティが高いほど倒産確率が高く, スプレッドは「非線形に」拡大する.

5.2 多項式回帰とスプライン

GAM に進む前に, スプレッドと株価ボラティリティ (equity_vol) の1変数の関係を, 曲線で当てはめる方法を確認する.

vol_lims <- range(bond$equity_vol)
vol_grid <- seq(from = vol_lims[1], to = vol_lims[2], length.out = 100)

多項式回帰

# 多項式回帰 (4次の直交多項式)
fit_poly <- lm(spread ~ poly(equity_vol, 4), data = bond)
coef(summary(fit_poly))

poly(x, 4)は, 互いに直交する4次までの多項式 (直交多項式) を生成する. 引数raw = TRUEとすると, \(x, x^2, x^3, x^4\) そのもの (非直交) となる. どちらでも予測値は同じであるが, 個々の係数の値は異なる.

スプライン

library(splines)
# B-スプライン (B-spline): 節点 (knots) を指定
fit_sp <- lm(spread ~ bs(equity_vol, knots = c(25, 35, 45)), data = bond)
pred_sp <- predict(fit_sp, newdata = list(equity_vol = vol_grid), se = TRUE)
plot(bond$equity_vol, bond$spread, col = "grey", xlab = "株価ボラティリティ (%)",
  ylab = "スプレッド (bp)")
lines(vol_grid, pred_sp$fit, lwd = 2)
lines(vol_grid, pred_sp$fit + 2 * pred_sp$se, lty = "dashed")
lines(vol_grid, pred_sp$fit - 2 * pred_sp$se, lty = "dashed")

# 自然スプライン (natural spline): 両端を直線に制約. 自由度で指定
fit_sp2 <- lm(spread ~ ns(equity_vol, df = 4), data = bond)
pred_sp2 <- predict(fit_sp2, newdata = list(equity_vol = vol_grid), se = TRUE)
plot(bond$equity_vol, bond$spread, col = "grey", xlab = "株価ボラティリティ (%)",
  ylab = "スプレッド (bp)")
lines(vol_grid, pred_sp2$fit, lwd = 2)
lines(vol_grid, pred_sp2$fit + 2 * pred_sp2$se, lty = "dashed")
lines(vol_grid, pred_sp2$fit - 2 * pred_sp2$se, lty = "dashed")

B-スプラインは, 端の方 (データが少ない領域) で曲線が暴れやすく, 信頼区間も広がりやすい. 自然スプラインは, 両端の外側で直線になるという制約を加えることで, これを抑えている.

# 平滑化スプライン (smoothing spline)
plot(bond$equity_vol, bond$spread, cex = 0.5, col = "darkgrey", xlab = "株価ボラティリティ (%)",
  ylab = "スプレッド (bp)")
fit_sp3 <- smooth.spline(bond$equity_vol, bond$spread, df = 30)  # 自由度 = 30 (柔らかすぎる)
fit_sp4 <- smooth.spline(bond$equity_vol, bond$spread, cv = TRUE)  # 交差検証で自由度を選択
fit_sp4$df
#> [1] 11.03971
lines(fit_sp3, col = "red", lwd = 2)
lines(fit_sp4, col = "blue", lwd = 2)
legend("topleft", legend = c("30 DF", paste(round(fit_sp4$df, 1), "DF (CV)")), col = c("red",
  "blue"), lty = 1, lwd = 2, cex = 0.8)

平滑化スプラインでは, 曲線の滑らかさを自由度 (df) で調整する. 自由度30 (赤) は柔らかすぎてデータの細かい変動まで追ってしまう (過学習). 交差検証 (cv = TRUE) で選ぶと, 自由度は約11となった (青).

5.3 パッケージgamの利用

関数gam() (パッケージ gam):
- 加法予測子のシンボリック表現や誤差分布を指定の上でGAMを当てはめる
- バックフィッティング・アルゴリズムを採用 (異なる平滑化やフィッティングの方法を混ぜられる)
- 局所回帰 lo() や平滑化スプライン s() をサポート
- usage:
  gam(formula, family = gaussian, data, weights, subset, na.action,
      start, etastart, mustart, control = gam.control(...),
      model = TRUE, method, x = FALSE, y = TRUE, ...)

summary()の “Anova for Nonparametric Effects” は, 各平滑化項について「線形の関係で十分か (非線形な部分は不要か)」を検定している. equity_volの非線形部分は強く有意であるのに対し, maturityの非線形部分は有意ではない.

gam()内で実行されている平滑化スプラインは, モデルの複雑さを示す自由度 (関数s()の2つ目の引数) の大きさで, 実質的に包含関係を表すことができる. すなわち, モデル間に包含関係 (ネスト, “nested”) がある場合には, 線形モデルの場合と同様に, 関数anova()を適用し, 両者のデータへの当てはまりの悪さ (逸脱度) の差の有意性を調べることで, モデルを複雑にすることの妥当性を定量的に評価することができる.

なお, モデル間に包含関係がない場合には, これまでと同様, AICやBICの大きさを比較することでモデルを選択すれば良い (パッケージgamを使用したモデル選択については, 以下の注意点を参照).

ここでは, 残存年数 maturity を「入れない」「線形で入れる」「平滑化スプラインで入れる」の3つのモデルを比べる.

fit_gam2 <- gam(spread ~ s(equity_vol, 4) + maturity + leverage + log_assets + industry,
  data = bond)

#> fit_gam1  7 5484.427

これより, モデル1と2の間には有意水準0.1%で差が見られるが, 2と3の間には (有意水準10%でも) 差は見られない. AICで比較しても, モデル2と3はほぼ同じで, モデル1より大幅に小さい. すなわち, この3つのモデルの中では, maturityを線形で加えたモデル2が妥当と言えそうである.

パッケージgamの使用に関する注意点

関数gam::gam()は, R言語の前身であるS言語から継承されてきた古い関数であり, 関数内部における計算 (バックフィッティング) の欠点が指摘されている.

その後, GAMの当てはめのアルゴリズムは今日までに種々提案されており, 次節で解説するパッケージmgcvは, 欠点を改善した それらの一つをRパッケージ化したものである.

また, パッケージgamのgam()の出力はクラス”glm”を継承していることから, 変数選択/モデル選択の際に使用する 関数anova()やAIC()の内部では, gam()の出力はクラス”glm”のオブジェクトとして処理され, それ自体が不正確さを もたらす可能性がある.

したがって, gamのgam()の推定結果や, その出力を使ったモデルの比較や選択は, 信頼性にやや欠ける点に注意が必要である.

補足:
gam の関数 s() は, 外から与える引数 df によって固定された自由度で平滑化スプラインを当てはめる.
一方, mgcv の s() は, データから平滑化パラメータを自動的に推定しつつ, 平滑化スプラインを当てはめる
("有効自由度" (ISLR, p.278) が推定される).
異なる滑らかさを持つモデル同士を比較する場合には, gam は公平なモデル比較をしているとは言えないため, mgcv の使用が良い.

関数名の衝突について

mgcvには, 先に見たgamと同じ名前の関数gam(), s()が 存在することから, 両方を読み込むと衝突 (コンフリクト) が生じる (“名前空間の衝突”と呼ぶ). Rでは, より後からlibrary()やrequire()で読み込んだパッケージの関数が優先される.

関数の衝突を確認する方法としては, 次のものがある.

# conflicts() # 一覧
find("gam")
#> [1] "package:mgcv"

関数の優先順位を入れ替える方法 (パッケージgamをmgcvよりも優先する場合) としては,

  1. 再度library()を実行する:
library(gam)
  1. detach()でパッケージを外す:
detach("package:mgcv", unload = TRUE)
  1. その都度「パッケージ名::関数名」を使う:
gam::gam(spread ~ ., data = bond)

がある. ただし, (3) の方法でも, s()が正しく解釈されないことがあるため, 上述のように, 一つのプログラムではどちらか一方のみを使うのが安全である.

5.5 パッケージprophetの利用

時系列予測を目的とした関数および補助関数のパッケージである. 非線形のトレンドと季節性・休日効果を足し合わせる加法モデルであり, GAM の考え方を時系列予測に応用したものと言える.

prophet:
- 非線形のトレンド + 年次・週次・日次の季節性 + 休日効果, の加法モデルに基づいて時系列を予測
- 強い季節性があり, 数シーズン分の過去データを持つ時系列に対して良く機能
- 欠損値やトレンドの変化に対して頑健. 通常, 外れ値もうまく処理する
- 出所: https://facebook.github.io/prophet/docs/quick_start.html#r-api
# install.packages('prophet')
library(prophet)

データ: ATM出金額 (仮想)

- atm_daily.csv, ある地方銀行の ATM 出金額 (日次, 百万円), 2023/1/1〜2025/12/31
  - date: 日付
  - amount: 出金額 (百万円)
atm <- read.csv("class/atm_daily.csv")
atm$date <- as.Date(atm$date)
plot(atm$date, atm$amount, type = "l", xlab = "", ylab = "出金額 (百万円)")

prophet による予測

休日効果として, 年末年始, ゴールデンウィーク, お盆の連休を指定する.

prophet の主な引数
- growth: "linear" (デフォルト), "logistic", "flat"
- changepoints (変化点): 日付ベクトルをユーザー指定 or 潜在的な変化点の自動選択 (デフォルト)

- yearly.seasonality (年次季節性): "auto" (デフォルト), TRUE, FALSE, 生成する Fourier 項の数
- weekly.seasonality (週次季節性): 同上
- daily.seasonality (日次季節性): 同上
- holidays (休日の指定): なし (デフォルト)
- seasonality.mode (季節性の入り方): "additive" (加法的, デフォルト), "multiplicative" (乗法的)
